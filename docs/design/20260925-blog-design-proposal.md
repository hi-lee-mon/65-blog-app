# ブログは「整った母屋」と「好き放題の展示室」の二層に分けて作る

作成日: 2026-09-25 / 状態: たたき台（未決定の論点あり）

## このメモで決めたいこと

やりたいことは三つある。見た目で遊ぶこと、技術力をアピールすること、新技術を試すこと。このうち「ページごとに好きな見た目にしたい」と「技術を見に来た人に読みやすく見せたい」はぶつかる。そこで、サイトを二つの層に分けることを提案する。

```
┌──────────────── サイト全体 ────────────────┐
│                                            │
│  【母屋】共通デザインシステムで統一         │
│   ホーム / プロフィール / 記事 / uses / now │
│   → 技術を見に来た人が迷わず読める場所     │
│                                            │
│  【展示室】ページごとに世界観を変えてよい   │
│   Lab（実験ページ） / デザインシステム見本  │
│   → 自分が楽しむ場所。新技術もここで試す    │
│                                            │
└────────────────────────────────────────────┘
```

この図から分かることは三つある。

- 技術を見に来た人が読むページは統一されるので、「読みにくい」で離脱されない
- 遊ぶページを隔離するので、一貫性がなくても全体は壊れない
- 展示室の作品は、そのまま「何が作れる人か」の証拠になる。遊びがアピールを兼ねる

決めてほしい論点は末尾にまとめた。

## ページ構成案

### 母屋（統一デザイン）

| パス            | ページ             | 中身                                                                                          | 主な読者         |
| --------------- | ------------------ | --------------------------------------------------------------------------------------------- | ---------------- |
| `/`             | ホーム             | 一行の自己紹介、最新記事3件、注目の Lab 作品、X・Zenn・GitHub へのリンク                      | 全員             |
| `/about`        | プロフィール       | 経歴、使える技術（技術ごとに、それを使った記事や Lab へのリンクを付ける）、連絡先             | 技術を見に来た人 |
| `/posts`        | 記事一覧           | 自サイトの記事を並べる。同じ記事を Zenn・Qiita にも出しているので、各記事から両方へリンクする | 全員             |
| `/posts/[slug]` | 記事詳細           | MDX 本文、目次、コードブロック、シェア用の画像（OGP）                                         | 全員             |
| `/tags/[tag]`   | タグ別一覧         | 技術ごとの記事と Lab                                                                          | 技術を見に来た人 |
| `/uses`         | 使っている道具     | エディタ、ターミナル、ライブラリなど                                                          | 開発者仲間       |
| `/now`          | 今やっていること   | 学習中の技術、次に試したいこと。月1回更新                                                     | 技術を見に来た人 |
| `/colophon`     | このサイトの作り方 | 技術スタック、ADR の一覧、テスト方針                                                          | 技術を見に来た人 |

`/about` の技術一覧は「React ★★★」のような自己採点より、「React: この記事とこの Lab で使った」とリンクで証拠を示すほうが信用される。記事や Lab に技術タグを付けておけば、一覧は自動で作れる。

記事の配り方は次の節で扱う。

### 展示室（ページごとに自由）

| パス             | ページ               | 中身                                                                                               |
| ---------------- | -------------------- | -------------------------------------------------------------------------------------------------- |
| `/lab`           | 実験一覧             | 作品をカードで並べる。成熟度、使った技術、作った日を表示                                           |
| `/lab/[slug]`    | 各実験               | ページごとに見た目も技術も自由。ページ下部に「試したこと・学んだこと」を共通の枠で添える           |
| `/design-system` | デザインシステム見本 | 色・文字・余白のトークン（デザインの値に名前を付けて一元管理したもの）と、自作コンポーネントの一覧 |

各 Lab ページの下に共通の枠を置くのは、自由なページを初めて見た人にも、何を試したのかが分かるようにするためだ。

### 裏方

`/feed.xml`（自分の記事の RSS）、`sitemap.xml`、各ページの OGP 画像、遊び心のある 404 ページ。アクセス解析には公開の最初から Cloudflare Web Analytics を入れる（ADR `20260925-1906-access-analytics.md`）。Next.js には sitemap と OGP 画像を作る仕組みが標準で入っている。

## 記事は1か所で書き、Zenn・Qiita・自サイトの3か所へ配る

同じ記事を3か所に公開すると決めた（ADR `20260925-1714-cross-post-articles.md`）。Zenn と Qiita は、どちらも「GitHub に push したら公開される」仕組みを公式に用意している。

- Zenn: 投稿用の公開 API はない。かわりに GitHub 連携があり、リポジトリ直下の `articles/` に置いた Markdown が公開される。連携できるリポジトリは2つまで（[手順の例](https://zenn.dev/kuuki/articles/20240609_github_to_zenn_first)）
- Qiita: 公式の Qiita CLI がある。`npx qiita init` で GitHub Actions の設定ファイルができ、push で投稿される（[手順の例](https://qiita.com/mk18/items/29e735f77ab8ebb93169)）

```
       原稿（1本の Markdown / MDX）
                 │
          GitHub に push
                 │
       GitHub Actions で変換
     ┌───────────┼────────────┐
     ▼           ▼            ▼
 Zenn 用       Qiita 用      自サイト
 articles/     public/       MDX のまま表示
 Zenn が公開   Qiita CLI     Next.js が表示
```

1つのリポジトリで Zenn と Qiita を管理している先行例がある（[sawasige さんの記事](https://zenn.dev/sawasige/articles/manage-qiita-and-zenn-in-one-repo)、[同時投稿の例](https://qiita.com/iineineno03k/items/67bcd2375f83244cfeca)）。

変換で吸収する差分は三つある。

1. **frontmatter（記事の先頭に書くタイトルやタグなどのメタ情報）の形式。** Zenn は `emoji`・`type`・`topics`・`published`、Qiita は `tags`・`private`・`id` などを使う。原稿には共通の形で書き、変換時にそれぞれの形へ直す
2. **独自の記法。** 補足の枠は Zenn だと `:::message`、Qiita だと `:::note` と書き方が違う
3. **動くデモ。** 自サイトの MDX に埋め込んだ React コンポーネントは、Zenn と Qiita では動かない。「デモは自サイトで動かせます」というリンクに置き換える

もう一つ、検索エンジンの扱いに注意が要る。同じ文章が3か所にあると、検索エンジンはどれが元記事か判断に迷う。本来は canonical（「この記事の正本はこちら」と検索エンジンに伝えるタグ）で示すが、Zenn も Qiita も canonical を設定できない（[Zenn の canonical を調べた記事](https://zenn.dev/zhener/articles/zenn-canonical-crosspost-seo)、[zenn-community の要望 Issue](https://github.com/zenn-dev/zenn-community/issues/78)）。記事の冒頭に「この記事は自サイトにも掲載しています」と書く、公開日をずらして元記事を先に出す、といった運用で補うのが一般的だ（[3つのルールの記事](https://qiita.com/Cosoado/items/4e7353d400340583c007)）。

マルチポストは当面の運用と位置づける。Zenn・Qiita から自サイトへ来る人が増え、自サイトの記事がたまってきたら、自サイトだけに投稿する運用へ切り替える。

## デザインシステムの作り方

Panda CSS（ビルド時に CSS を生成するスタイリングライブラリ。Server Components でも動く）は、二層構成と相性がよい。トークンを三段に分ける。

```
① 基本トークン   色の実値・文字サイズ・余白の段階（例: blue.500 = #3b82f6）
      ↓ 名前を付け替える
② 意味トークン   用途の名前（例: 本文の文字色、主要ボタンの背景色）
      ↓ ページごとに上書きする
③ ページテーマ   Lab の各ページで ② の中身だけ差し替える
```

母屋は ② までを使う。展示室は ③ で意味トークンを差し替えれば、同じコンポーネントのまま別世界の見た目になる。コンポーネントを作り直さずに済むのが利点だ。Panda の theme 機能で実現できるかは、実装前に公式ドキュメントで確認する。

参考にするデザインシステムは役割で分けると迷わない。[デジタル庁デザインシステム](https://design.digital.go.jp/)は母屋の読みやすさとアクセシビリティ（色のコントラスト、文字サイズ、フォーカスの見え方）の手本にする。Apple の Human Interface Guidelines は、動きや手触りの気持ちよさの手本にする。

コンポーネントは Mantine の作りを参考にする。たとえば、見た目の部品を外から差し替えられる Styles API や、`@mantine/hooks` の小さなフック群が参考になる。作る順番は、よく使う順がよい。

1. 文字と余白の土台（Text, Title, Stack, Group）
2. 記事ページで必要なもの（Anchor, Badge, Card, CodeBlock）
3. 触って楽しいもの（Tooltip, Tabs, Modal など）

作るたびに `/design-system` に並べていけば、見本ページが育っていく。

## 新技術を試す場所としての使い方

Lab の1ページを1つの実験にすると、試した技術が散らからない。たとえば次のようなものがある。

- React の `<ViewTransition>` を使ったページ遷移のアニメーション（Next.js 16 の同梱ドキュメント `view-transitions.md` にガイドがある）
- Next.js の Cache Components
- テスト。同梱ドキュメントには Vitest、Playwright、Jest、Cypress のガイドがある。コンポーネントは Vitest、画面操作は Playwright、という分け方がよく使われる

## 対象外にしたこと

ホスティング先、ドメイン、コメント機能やいいねボタンのようなデータベースが要る機能は、今回は論じていない。二層構成が決まってから考えても遅くないためだ。

## 決めてほしい論点

1. **技術記事の置き場所。** 決定済み。同じ記事を Zenn・Qiita・自サイトの3か所に配る（ADR `20260925-1714-cross-post-articles.md`）
2. **原稿を置くリポジトリ。** 決定済み。このリポジトリの直下に `content/`・`articles/`・`public/` を置き、`blog-app/` と同居させる（ADR `20260925-1907-content-in-same-repo.md`）
3. **正本をどこにするか。** 決定済み。自サイトを正本にし、Zenn・Qiita 版の冒頭に自サイトへのリンクを置く（ADR `20260925-1913-canonical-own-site.md`）
4. **原稿の読み込み方。** 決定済み。unified で自前に組み、Next.js に依存させない（ADR `20260925-1914-unified-content-pipeline.md`）
5. **シンタックスハイライター。** 決定済み。ビルド時に Shiki で色を付ける。gpu-lexer は Lab で試す題材にする（ADR `20260925-1923-syntax-highlighter-shiki.md`）
6. **二層構成。** 決定済み（ADR `20260925-1702-two-layer-site-structure.md`）
