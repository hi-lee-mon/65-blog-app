# Storybook の寄り道を保留にし、公開できる見た目（ナビ・付箋ページ・トップ画面）を先に作る

- 日付: 2026-11-15
- 状態: 採用
- 置き換えるもの: ADR `20261111-0041-storybook-detour.md` の進める順番（2-7〜2-13 は、この段のあとに回す）

## 背景

2-6 で Storybook を入れ、2-7（addon-vitest で部品のテストを書く）のチケットまで作った。本人はここで、サイトを公開できる見た目に整えるほうを先にしたいと考えた（2026-11-15）。

- トップ画面と、ほかの画面の実装が終わっていない。今の画面はまだ見づらい
- 記事より軽い「記事の種」を書く場所がほしい。付箋のカードを弁当レイアウトで並べ、日付とタグで並べ替えられるページを考えている
- トップ画面に、自分の X のツイートを出したい
- グローバルナビゲーションとパンくずリストを整えたい

## 決めたこと

「公開できる見た目」の段を 3-0 から 3-7 の8回で進める（3-0 は 2026-11-15 に足した。下の「3-0 を足した理由」）。2-7〜2-9（Storybook の寄り道）と、2-10 以降はこの段のあとに戻る。2-7 のチケット（`tickets/2-7-component-tests.md`）と ADR `20261115-2106-component-tests-with-addon-vitest.md` は、そのまま保留にする。

| Step | 内容                                                                                    |
| ---- | --------------------------------------------------------------------------------------- |
| 3-0  | 公開しているページを axe で自動検査し、WCAG の違反があれば落ちる仕組みを作る            |
| 3-1  | ヘッダー（グローバルナビゲーション）とフッターを作り、全ページに置く                    |
| 3-1b | リンクを押してから移動が終わるまで、待っていることが分かる動きを付ける（useLinkStatus） |
| 3-2  | パンくずリストを作る                                                                    |
| 3-3  | 付箋の原稿の置き場所を決め、弁当レイアウトで一覧にする                                  |
| 3-4  | 付箋を日付とタグで並べ替える                                                            |
| 3-5  | トップ画面を作る（自己紹介、最新の記事と付箋）                                          |
| 3-5b | OGP 画像をデザインし、X のアイコン画像とサイト名・記事の題を載せる                      |
| 3-6  | トップ画面に X のツイートを出す                                                         |
| 3-7  | 記事一覧・タグ一覧・about を整える                                                      |

## 理由

- ヘッダーとフッターは全ページで使う。パンくずリストは、ナビゲーションで決めたページの階層に沿って作るので、その次に置く
- トップ画面に「最新の付箋」を出すので、付箋ページをトップ画面より先に作る
- X のツイートは外部サービスに頼り、費用と表示の確かさで決めることが多いので、後ろに置く
- 付箋ページは、書きかけのメモを公開して育てる「デジタルガーデン」の考え方と同じ形をしている。Maggie Appleton はメモを「芽（seedling）→ つぼみ（budding）→ 常緑（evergreen）」の3段階で育てており、「記事の種」はこの「芽」にあたる。先行事例があるので、独自の形を考えるより、そこから取り入れる

### 3-0 を足した理由

本人は、このサイトを a11y にいちばん注意して作りたいと考えている（2026-11-15）。自動検査を先に入れておけば、3-1 以降に作るヘッダー、付箋ページ、トップ画面は、作った時点から検査される。後から入れると、それまでに作ったページの違反をまとめて直すことになる。Storybook の 2-8 で部品ごとに検査する計画はあるが、ヘッダーと本文の組み合わせのようなページ全体の問題は、部品ごとの検査では見つからない。

自動検査で見つかるのは WCAG の問題の一部（Deque の調査では件数で 57%）なので、各チケットの受け入れ条件に、キーボード操作やフォーカスの見え方などを手で確かめる項目も入れる。

### 3-1b を足した理由

リンクを押してから移動が終わるまでの間に、待っていることが分からない（本人の指摘、2026-11-15）。Next.js 16.4 には、リンクごとに移動待ちの状態を返す `useLinkStatus` がある。3-1 で作るナビゲーションのリンクにすぐ使えるので、3-1 の直後に置く。番号は 3-2 以降を変えないよう枝番にした。動きを減らす設定（`prefers-reduced-motion`）と、読み上げソフトへの伝え方も、この回で決める。

### 3-5b を足した理由

本人が、X のアイコン画像を載せた OGP 画像を作りたいと考えた（2026-11-15）。今の OGP 画像は、白い背景にサイト名か記事の題を置いただけになっている。トップ画面（3-5）でサイトの顔（自己紹介や配色）が決まってから作れば、同じ雰囲気にそろえられるので、3-5 の直後に置く。アイコン画像は本人が保存してリポジトリに置き、ビルドのたびに X から取りには行かない。`next/og` で日本語の字体が描けるか、画像の代替テキストと文字のコントラストも、この回で確かめる。

## 採らなかった案

- **Storybook の寄り道を続ける（2-7 から）。** 部品のテストと a11y の検査の仕組みが先にそろうが、公開できる見た目になるのが遅れる
- **付箋ページから作る。** いちばん作りたいページに早く着手できるが、ヘッダーとパンくずリストを後から全ページに足すことになる
- **トップ画面から作る。** サイトの顔が先に整うが、「最新の付箋」を出す場所が、付箋ページができるまで空く

## 気をつけること

- 3-1 のナビゲーションは、React Aria の回（2-11）より先に作ることになる。3-1 では状態を持たない形（リンクを並べる）で作り、開閉するメニューが要るなら React Aria の回で置き換える
- 付箋ページの名前と URL は 3-3 で決める。「Post-it」は 3M の登録商標なので、推奨は画面の名前を「付箋」、URL を `/notes` にする案
- 弁当レイアウトで高さの違うカードを隙間なく詰める並べ方（masonry）は CSS の `grid-lanes` で書けるが、2026-11 時点で安定版が対応しているのは Safari 26.4 以降だけ。普通の CSS Grid で組み、対応ブラウザでだけ詰める形を 3-3 で検討する
- X の表示方法は 3-6 で決める。2026-11-15 に調べた時点の選択肢は次のとおり
  - 公式の埋め込みタイムライン: 無料だが、X にログインしていない人には表示されないという報告が多い
  - X API: 2026-02 から従量課金。自分の投稿の取得は1件 $0.001 とする第三者の資料がある（公式の資料では未確認）。開発者登録、カード、鍵の管理が要る
  - `react-tweet`（3.3.1）: 選んだツイートを、X のスクリプトを読み込まずにサーバー側で描ける。無料だが、X の非公式の仕組み（syndication API）に頼る。最新のツイートは自動では出ない
- 原稿の読み込みを Next.js に依存させない制約（ADR `20260925-1914-unified-content-pipeline.md`）は、付箋の原稿にも当てる
