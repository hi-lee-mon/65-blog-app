# 見た目をそろえる値はトークンだけで書き、角かっこ（エスケープハッチ）は時間などに限る

- 日付: 2026-11-20
- 状態: 採用

## 背景

`strictTokens: true` にしてあるので、`css()` にはトークンの一覧にある値しか書けない（ADR `20261107-1637-primitive-values.md`）。ただし、`"[12rem]"` のように角かっこで囲めば、一覧にない値も書けてしまう。この書き方をエスケープハッチと呼ぶ。

今は `link-pending-dot.tsx` の3か所（`[100ms]`・`[1.6s]`・`[ease-in-out]`）で使っている。3-3b では、付箋の高さの上限やダイアログの背景の色など、トークンにない値が続けて出てくる。決まりがないまま書くと、似た値が少しずつ違う形で増え、デザインシステムでそろえた意味がなくなる。

もう1つ穴がある。`gridTemplateColumns` や `maskImage` のように、値を文字列で丸ごと書くプロパティは、Panda がトークンかどうかを検査しない。3-3 の `minmax(min(100%, 16rem), 1fr)` の `16rem` は、角かっこなしで型検査を通る。

## 決めたこと

1. `css()` の値は、原則としてトークンから選ぶ
2. **見た目の一貫性を決める種類には、エスケープハッチを使わない。** 色・余白・文字の大きさ・行の高さ・幅と高さ・角丸・枠線の太さがこれにあたる。一覧にない値が要るときは、トークンを足す。名前の付け方は今の決まりに合わせる（長さは px の数、値は `rem`）。色は、部品から使えるように意味トークン（`theme/semantic.ts`）を足す
3. **上に入らない種類は、1か所でしか使わない値に限って、エスケープハッチを使ってよい。** 時間・イージング（動きの速さの変化）・重なり順（`z-index`）など、まだトークンを作っていない種類がこれにあたる。使うときは、その値にした理由をコメントに書く
4. 同じ値が2か所目で要るようになったら、その種類のトークンを作り、2か所とも移す
5. Panda が検査しないプロパティと `globalCss` の中でも、2の種類の値はトークンを参照して書く。書き方は `{sizes.640}` か `token(sizes.640)` で、どちらも `var(--sizes-640)` に置き換わる（2026-11-20 に一時ディレクトリで確かめた）。割合（`100%`）、`fr`、`0`、`auto` のようなキーワードは対象外
6. 2の種類でも、角かっこの中がトークンの参照・割合・キーワード・CSS の関数（`min()`・`calc()` など）だけでできているなら、エスケープハッチを使ってよい。新しい値を持ち込まず、トークンの組み合わせを計算しているだけだから。例: `maxWidth: "[min({sizes.640}, 100% - {spacing.32})]"`（3-3b のダイアログ。ビルドで `min(var(--sizes-640), 100% - var(--spacing-32))` になることを確かめた）
7. この決まりから外れる必要が出たら、その回の ADR に理由を書く

## 理由

- 色と長さは、サイト全体の見た目がそろうかどうかを決める。一覧で管理していれば、変えるときもトークンの1か所を直せば済む
- 色を意味トークンにそろえるのは、ダークモードの値とコントラスト比を1か所で確かめるため（ADR `20261107-1722-semantic-colors.md`）
- 時間やイージングは、今はまだ1か所でしか使っていない。使う場所が1つのうちにトークンを作っても、名前を考える手間に見合わない。2か所目が出た時点で、そろえる相手ができる
- 理由のコメントを求めるのは、トークンにしなかった値ほど、あとで「なぜこの数なのか」が分からなくなるため

## 採らなかった案

- **エスケープハッチを一切禁止する。** 決まりは単純になる。ただ、1か所でしか使わない時間の値のために、毎回トークンを作ることになる
- **使う人の判断に任せる（今のまま）。** 手間はない。ただ、似た値が少しずつ違う形で増えていく
- **検査で止める（`oxlint-plugins/` に規則を足す）。** 守れているかを機械で確かめられる。ただ、2の種類か3の種類かを見分ける規則を書く手間が大きい。違反が実際に増えてきたら考える

## 気をつけること

- 今の3か所（`link-pending-dot.tsx`）は、3の種類（時間・イージング）で1か所ずつなので、この決まりに収まる。ただし `[100ms]` には値の理由のコメントがない。次にこのファイルを触るときに足す
- 3-3 の `16rem` は5に当たるので、`sizes` にトークンを足して参照する形に直す（3-3 のチケットに反映した）
- `theme/` の中のトークンの値そのものは、この決まりの対象外。値を定義する場所だから
