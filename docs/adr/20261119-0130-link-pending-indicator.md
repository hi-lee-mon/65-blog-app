# リンクを押してから移動が終わるまでの待ちを、`useLinkStatus` の小さな点で示す

- 日付: 2026-11-19
- 状態: 採用（2026-11-19）
- 関連: ADR `20261115-2117-publishable-home-before-storybook.md`（3-1b を足した理由）、ADR `20261115-2130-site-header-footer.md`（ナビの作り）

## 背景

ヘッダーのリンクを押してから次のページが出るまでの間、画面に変化がない。待っていることが分からず、押し直す原因になる（本人の指摘、2026-11-15）。

Next.js 16.4 には、リンクごとの待ちの状態を返す `useLinkStatus` がある。同じ文書は、先読みと `loading.js` を先に検討し、`useLinkStatus` は補助として使うよう勧めている。

## 決めたこと

- 待ちの表示は、`NavLink` の中に置く小さな点（`LinkPendingDot`）で示す。点は `useLinkStatus` で待ちの状態を読む
- 記事カード（`PostCard`）のリンクにも同じ点を置く。遅い回線で押したときに反応が分からないのは、ナビと同じため。`PostCard` は Server Component のままにし、`Link` の中に点の部品を置くだけにする（2026-11-19 追記）
- サイト内のページ移動に使うリンクは、すべて共通の部品（仮の名前 `AppLink`）を通す。`next/link` を包み、中に点を入れる。対象は `NavLink`、`PostCard`、ヘッダーのロゴ、`Tag`、フッターの「デザインシステム」、トップページの一覧の 6 か所。同じページの中の移動（スキップリンク、目次）と外部サイトのリンクは対象外。前者は待ちが起きず、後者は `useLinkStatus` が見ないため（2026-11-19 追記）
- 点は文字の外に浮かせ（`position: absolute`）、出ていないときに幅を取らないようにする。タグや文章中のリンクに、常に空白ができるのを避けるため（2026-11-19 追記）
- 点の大きさは固定し、`opacity` で出し入れする。文字の位置を動かさない
- 点は `aria-hidden` で読み上げから隠す
- 点の出し入れのフェードは、動きを減らす設定（`prefers-reduced-motion: reduce`）のときも残す。WCAG 2.2 の 2.3.3 の解説書は、要素の位置・大きさ・形が変わらない不透明度の変化を「動きのアニメーション」に含めていないため（2026-11-19 改訂。当初は「アニメーションを止める」としていた）
- 点が出るときだけ 100ms 遅らせ、速い移動では点を出さない。Next.js のガイド「Gracefully handling fast navigation」に沿う（2026-11-19 追記）
- 点は待っている間、1 周 2 秒でゆっくり点滅させる（不透明度 1 → 0.5 → 1）。繰り返しは 2 回（4 秒）までにし、その後は点けたままにする。5 秒を超える自動の点滅に停止手段を求める WCAG 2.2.2 に収めるため。点滅の動きは `panda.config.ts` の `keyframes`（`linkPendingPulse`）に置く（2026-11-19 追記）
- 点の色は `currentColor`（リンクの文字と同じ色）にする。リンクの文字が 4.5:1 を満たしていれば、点に求められる 3:1（WCAG 1.4.11）も満たすため（2026-11-19 追記）
- 点の大きさのために、`theme/tokens.ts` の `sizes` に `8`（0.5rem）を足す。このリポジトリは `preset-base` だけを使っており、`sizes` に `spacing` の値が混ざらないため（2026-11-19 追記）
- 先読みは Next.js の既定のまま切らない
- ページ全体の読み込み表示（`loading.js`）は、この回では作らない

## 採らなかった案

- **`usePathname` と `useState` で自分で待ちを管理する。** 移動の開始と終わりを自分で捕まえる必要があり、ずれやすい
- **先読みを切って、常に待ちを見せる。** ナビのリンクは数が少なく、先読みで押した瞬間に切り替わるほうが速い
- **`loading.js` を足す。** 今のページは静的で、遷移が一瞬で終わるため効きにくい
- **点を置くリンクごとに `LinkPendingDot` を書く。** 新しいリンクを足すたびに入れ忘れが起きる
- **点の幅を常に取っておく（`opacity: 0` で隠すだけ）。** ナビでは目立たないが、タグや文章中のリンクの右に、常に空白ができる
- **点をやめ、リンクの文字を薄くして待ちを示す。** 空白はできないが、薄くした文字がコントラストの基準を下回るおそれがある

## 確認事項の推奨と理由・欠点

確認事項は、チケットの「確認事項」と同じ内容。

1. **先読みを切るか。** 推奨は「切らない」。理由は、ナビのリンクが少なく、先読みで速く切り替わるため。欠点は、先読み済みのリンクでは点がほとんど出ないこと
2. **移動中を読み上げに伝えるか。** 推奨は「伝えない（`aria-hidden`）」。理由は、名前を変えると読み上げのたびに「移動中」の声が混ざるため。欠点は、読み上げの利用者が待ちを知る手がかりがないこと。実機で確かめた結果は、下の「確かめた結果」に書き足す
3. **待ちの見せ方。** 推奨は「色のついた点の出し入れ」。理由は、文字がずれないため。欠点は、点だけでは何の待ちか伝わりにくいこと
4. **動きを減らす設定のとき。** 「フェードも残す」に改めた（2026-11-19）。理由は、不透明度の変化は物が動かず、2.3.3 の対象外のため。欠点は、フェードも含めて一切の変化を嫌う人には合わないこと。当初の推奨は「出し入れは残し、アニメーションだけ止める」だった
5. **`loading.js` も作るか。** 推奨は「作らない」。理由は、今のページがすべて静的なため。欠点は、動的なページを作るときに改めて足す必要があること

## 影響

- ナビの `NavLink` と記事カードのリンクに点が増える。文字の位置は変わらない
- 先読みの設定は変えない。通常の回線では点はほぼ出ない
- 点の色は `currentColor` を使う。リンクの文字の色に従う
- 点は文字の外にはみ出す。小さいタグ（`size: "sm"`、左右の余白 8px）では、点が枠線にかかるおそれがある（未確認。目視で確かめる）
