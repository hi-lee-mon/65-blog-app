# ページの幅と見出しを PageContainer と PageHeader にまとめる

- 日付: 2026-11-22
- 状態: 採用
- 関連: ADR `20261115-2117-publishable-home-before-storybook.md`（公開できる見た目の段）、ADR `20260925-1702-two-layer-site-structure.md`（母屋と展示室）、ADR `20261119-2126-breadcrumb.md`（パンくずリスト）

## 背景

パンくずと見出しを持つページが5つになった。幅と余白があるのは `/notes` と `/posts/[slug]` だけで、`/posts`・`/tags`・`/tags/[tag]` は文字が画面の左端に張り付いている。見出しの大きさも記事の詳細ページだけ違う。本人が、この3種類の一覧の左上は統一できると考えた（2026-11-22）。

## 決めたこと

1. 3-3c として 3-4 の前に置き、3-7 の「幅をそろえる」作業を前倒しする
2. `PageContainer`（幅と余白）と `PageHeader`（パンくず、`<h1>`、説明文）の2部品にする
3. 見出しと幅に `layout.tsx` は使わない
4. `/posts`・`/tags`・`/tags/[tag]`・`/notes` は両方を使い、`/posts/[slug]` は `PageContainer` だけを使う
5. 幅は今の記事ページと同じ 640 にする
6. 見出しはすべて `heading.1` にする
7. パンくずの現在地は、指定がなければ見出しと同じ文字にする
8. 説明文は `description` として任意で渡す
9. 展示室の `/design-system` は変えない

## 採らなかった案

- **幅と見出しを1つの部品にする。** 呼ぶのは1回で済むが、`<h1>` を `<article>` の中に置く記事の詳細ページが例外になる
- **Route Group の `layout.tsx` で幅を持たせる。** ページ側の指定はなくなるが、ページのフォルダを移動することになる。Next.js のレイアウトは移動しても描き直されないので、ページごとの見出しは結局共通化できない
- **ルートの `layout.tsx` で幅を持たせる。** 変更は1か所で済むが、見た目を自由にする展示室にも幅がかかる

## 確認事項の推奨と欠点

- チケットの位置: 学習計画の順番が少し変わり、3-7 の作業が減る
- 2部品にする: 各ページで2つの部品を呼ぶ
- `layout.tsx` を使わない: 新しいページで部品を呼び忘れるおそれがある
- 対象のページ: 記事の詳細ページだけ、パンくずを直接呼ぶ形が残る
- 幅を 640 にする: 付箋が2列までしか並ばない
- 見出しを `heading.1` にする: 一覧ページの見た目が変わる
- 現在地の既定値: `/tags/[tag]` だけ `current` の指定が要る
- 説明文を持たせる: `PageHeader` の役割が少し増える
- 展示室を変えない: 同じ幅の指定が `/design-system` に残る

## 確かめた結果

2026-11-22 に、作業中の 3-3b を含むリポジトリの複製で確かめた（next 16.4.6、react 19.3.1、bun 1.4.4）。

- チケットの手順どおりに置き換えると、`bun run tc`、`bun run l`、`bun run fc` が通った
- `bun run ay` が明るい表示と暗い表示の両方で通り、WCAG 2.2 AA の違反は 0 件だった
- `title` を渡さないと `bun run tc` が `TS2741` で失敗した

未確認: ブラウザでの見た目、VoiceOver の読み上げ。

## 今後

- 付箋を3列以上で見せたくなったら、`PageContainer` に幅の指定を足す
- 3-7 では about を同じ部品で作る
