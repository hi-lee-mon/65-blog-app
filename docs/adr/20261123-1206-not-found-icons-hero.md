# X のアイコンをファビコンとヒーローに使い、404 ページで次の行き先を案内する

- 日付: 2026-11-23
- 状態: 採用（2026-11-23。目視、404 のステータス、VoiceOver は未確認のまま本人が了承。チケット `tickets/3-11-not-found-and-icons.md`）
- 関連: ADR `20261122-1821-publish-first-path.md`（公開までの順番）、ADR `20261122-2332-top-page.md`（トップ画面）

## 背景

サイトにはファビコンも自作の 404 ページもなく、トップ画面に書き手の顔が見えない。本人が、ファビコンとヒーローには X の画像を使ってよいと判断した（2026-11-23）。

## 決めたこと

1. X のアイコンを本人が保存し、リポジトリに置く
2. 元の画像は `app/_assets/avatar.png` に置く
3. ファビコンは `app/icon.png`（192px）と `app/apple-icon.png`（180px）にする
4. ヒーローは 96px の丸いアイコン、サイト名、自己紹介で作る。画像は `preload` を使わず、遅延読み込みと `placeholder="blur"` にする（本人の判断。文字の表示を優先するため）
5. ヒーロー画像は `alt=""` にする
6. 404 ページは落ち着いた日本語の案内にし、赤を使わない
7. 404 ページからトップ、記事一覧、タグ一覧へ案内する
8. 存在しない記事とタグの URL が HTTP 200 を返す動きは、今回は直さない

## 採らなかった案

- **ビルドのたびに X から画像を取得する。** アイコンの変更に追従できるが、X の障害や仕様変更でビルドが止まる
- **`public/` に画像を置く。** 一般的な置き方だが、このリポジトリの `public/` は Qiita CLI 用に予約している
- **`favicon.ico` も作る。** 古いブラウザに対応しやすいが、ico を作る道具が別に要る
- **`icon.tsx` でアイコンを生成する。** 文字や色をコードで変えられるが、X のアイコンをそのまま使う今回には過剰

## 確認事項の推奨と欠点

- 本人が保存する: X のアイコンを変えても自動では変わらない。リポジトリは public なので画像も公開される
- `app/_assets/` に置く: 一般的な `public/` の置き方と違う
- PNG のアイコンだけにする: とても古いブラウザでは出ないことがある
- 96px のヒーロー: 全面の大きな画像ほどの印象は出ない
- 遅延読み込みとぼかし: 画像の表示が少し遅れ、HTML が約1.1KB増える
- `alt=""`: 説明が要る画像に変えたら書き直しが要る
- 落ち着いた案内: 設計書にある「遊び心」はまだ入らない
- 3つの行き先: ふせんへの導線がページ内にない
- HTTP 200 を残す: 監視ツールやクローラーが正常なページと誤解する場合がある

## 確かめた結果

2026-11-23 に、リポジトリの複製とダミー画像でチケットの手順を流した（next 16.4.6、react 19.3.1、bun 1.4.4、Node.js 24.22.1）。

- `/no-such-page` は 404 を返し、自作の案内と `noindex` が出た
- `/posts/no-such-post` と `/tags/nosuchtag` は案内と `noindex` が出たが、ステータスは 200 だった
- `<head>` に `192x192` の icon と `180x180` の apple-touch-icon が出た
- 320px、375px、1280px の幅で横スクロールは出なかった
- `bun run l`、`bun run fc`、`bun run tc`、`bun run ay` が通った
- `alt` を消すと `bun run tc` が `TS2741` で失敗した
- 低速回線の再現では LCP は見出しで、`preload` を外すと画像の取得開始が 175ms から 584ms に下がった。最初の表示の差は 40ms で、1回の測定では誤差の範囲だった

未確認: 実際の X のアイコンでの見た目、VoiceOver の読み上げ、実機での表示。
