## なぜこれをやるか

1-8 で公開したサイトでは、どのページのタブも「Create Next App」、SNS のカードの説明文は「Generated by create next app」になっている。記事の URL を貼っても、どこの誰のサイトかが伝わらない。

もう1つの狙いは、Next.js のメタデータが親と子でどう合わさるかを知ることにある。親（`layout.tsx`）に書いた値と子（`page.tsx`）に書いた値は、項目ごとに「丸ごと上書き」される。中身の一部だけを足すことはしない。この決まりを知らずに書くと、エラーは出ないまま、SNS のカードだけがおかしくなる。

## 周辺知識

### メタデータの合わさり方（出典: `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/generate-metadata.md` の Merging）

- 親から子の順に評価し、同じ項目は**後のもの（子）で丸ごと置き換える**。`openGraph` のような入れ子の項目も中身を混ぜずに丸ごと置き換える
- 子がその項目を書かなければ、親の値を**丸ごと受け継ぐ**

### `title` の型（出典: 同じファイルの `title.template`）

- `title: { default, template }` の形で書く。`template` の `%s` に子のページのタイトルが入る
- `template` は**子のセグメントにだけ**効く。同じ `layout.tsx` の中や、タイトルを持たないページには効かない
- `template` を書くときは `default` も必須。タイトルを持たないページには `default` が出る

### 準備：この回で何をするのか

サイトの名前を `65banseki の技術ブログ` に決め、どのページのタブにも「ページ名 | 65banseki の技術ブログ」と出るようにする。SNS のカードにもサイト名と日本語のサイトであることを載せる。その途中で、親のレイアウトと子のページのメタデータがどう合わさるかを、壊しながら確かめる。

#### メタデータは「名札の重ね貼り」

Next.js はいちばん外の `app/layout.tsx` から、ページの `page.tsx` まで順に名札を重ねて貼る。決まりは2つだけだ。

```
親（layout.tsx） ┌ title: サイト名           ┐
                 │ openGraph: { サイト名, 言語 } │
                 └──────────────────────┘
子（page.tsx）    ┌ title: 記事一覧           ┐   ← 同じ項目は、子の名札で丸ごと隠れる
                 └──────────────────────┘   ← 子が書かない項目（openGraph）は、親の名札が見える
```

- 同じ項目を子が書くと、親の名札は**丸ごと**隠れる。`openGraph` の中の1項目だけを書いても、親の `openGraph` は全部隠れる
- 子が書かない項目は、親の名札がそのまま見える

この「丸ごと」が手順 7 と手順 8 でつまずく原因になる。

### 手順 7：記事ページを「記事」として名乗らせ、サイト名が消えるのを直す（この回の本題）

いまは記事ページの `og:type` も `website` になっている。記事ページだけ `article` にし、公開日も付ける。

#### 7-a：素直に `openGraph` を書く

`app/posts/[slug]/page.tsx` の `generateMetadata` の `return` を書き換える。

```tsx
return {
  title: post.frontmatter.title,
  openGraph: { type: "article", publishedTime: post.frontmatter.date },
};
```

```bash
bun run build
grep -o '<meta property="\(og:title\|og:site_name\|og:locale\|og:type\|og:image\|article:published_time\)"[^>]*>' .next/server/app/posts/hello.html
```

```
<meta property="og:title" content="はじめての記事 | 65banseki の技術ブログ"/>
<meta property="og:type" content="article"/>
<meta property="og:image" content="https://www.65banseki.dev/posts/hello/opengraph-image?0203e9bf893d0cb0"/>
<meta property="article:published_time" content="2026-09-25"/>
```

`og:type` は `article` になり、公開日も付いた。ところが、手順 6 で出ていた `og:site_name` と `og:locale` が**消えている**。エラーも警告も出ない。

#### 7-b：共通部分を自分で引き継ぐ

`import` に1行足す。

```tsx
import { siteOpenGraph } from "../../../lib/siteMetadata";
```

`return` を書き換える。

```tsx
return {
  title: post.frontmatter.title,
  openGraph: {
    ...siteOpenGraph,
    type: "article",
    publishedTime: post.frontmatter.date,
  },
};
```

同じ `grep` を実行する。

```
<meta property="og:title" content="はじめての記事 | 65banseki の技術ブログ"/>
<meta property="og:site_name" content="65banseki の技術ブログ"/>
<meta property="og:locale" content="ja_JP"/>
<meta property="og:type" content="article"/>
<meta property="og:image" content="https://www.65banseki.dev/posts/hello/opengraph-image?0203e9bf893d0cb0"/>
<meta property="article:published_time" content="2026-09-25"/>
```

**何が起きていたのか** — 準備の「名札の重ね貼り」の1つ目の決まりだ。記事ページが `openGraph` を書いたので、親の `openGraph`（サイト名と言語）は**丸ごと**隠れた。Next.js は「`type` だけ書き足したい」とは読まない。だから、親から引き継ぎたい部分は子の側で自分でもう一度書く。`lib/siteMetadata.ts` に切り出したのは、この「もう一度書く」を1行で済ませるためだった。

**`og:image` が消えなかった理由** — 画像は `metadata` ではなく、同じフォルダの `opengraph-image.tsx` から付く。ファイルで付けたものは `openGraph` を書いても隠れない。

**この発見が今後どこに効くか** — `robots`（検索エンジンへの指示）や `alternates`（正規の URL）など、入れ子の項目はどれも同じ決まりで動く。子で書いたら、親の値は消えると思っておく。おかしいと気づくきっかけはエラーではなく、ビルドした HTML を見ることしかない。

```tsx
  openGraph: {
    title: SITE_NAME,
    ...siteOpenGraph,
    type: "website",
  },
```

```bash
bun run build
for p in posts/hello posts tags/mdx; do echo "-- $p"; grep -o '<title>[^<]*</title>\|<meta property="og:title"[^>]*>' .next/server/app/$p.html; done
```

```
-- posts/hello
<title>はじめての記事 | 65banseki の技術ブログ</title>
<meta property="og:title" content="はじめての記事 | 65banseki の技術ブログ"/>
-- posts
<title>記事一覧 | 65banseki の技術ブログ</title>
<meta property="og:title" content="65banseki の技術ブログ"/>
-- tags/mdx
<title>タグ: mdx | 65banseki の技術ブログ</title>
<meta property="og:title" content="65banseki の技術ブログ"/>
```

ブラウザのタブはどのページも正しい。ところが SNS のカードのタイトルは、`/posts` も `/tags/mdx` もサイト名（`65banseki の技術ブログ`）になった。記事ページだけは無事だ。

**何が起きたのか** — 準備の2つ目の決まりだ。`/posts` と `/tags/mdx` は `openGraph` を書いていないので、親の `openGraph` が丸ごと見える。その中に `title: SITE_NAME` があるので、`og:title` はそれになる。記事ページが無事だったのは、手順 7-b で自分の `openGraph` を書き、親の `openGraph` を丸ごと隠していたからだ。手順 6 で `og:title` に型が効いていたのは、親の `openGraph` に `title` が**なかった**ので補われていただけだった。X のカードも `og:title` を写すので、同じタイトルになる。

確かめたら、`layout.tsx` の `title: SITE_NAME,` を消す。`bun run build` のあと、`/posts` の `og:title` が `記事一覧 | 65banseki の技術ブログ` に戻ることを確かめる。

### 手順 9：トップページのシェア用の画像を作る

いまトップページの URL を X に貼ると、大きな画像用のカード（`summary_large_image`）なのに、載せる画像がない。1-7 と同じやり方で、サイト名だけを載せた画像を作る。

`app/opengraph-image.tsx` を新しく作る。置き場所は `app/` の直下で、1-7 の `app/posts/[slug]/` ではない。

```tsx
import { ImageResponse } from "next/og";
import { SITE_NAME } from "../lib/siteMetadata";

export const size = { width: 1200, height: 630 };
export const contentType = "image/png";
export const alt = "サイト名を載せた画像";

export default function Image() {
  return new ImageResponse(
    <div
      style={{
        width: "100%",
        height: "100%",
        display: "flex",
        alignItems: "center",
        justifyContent: "center",
        background: "white",
        fontSize: 80,
      }}
    >
      {SITE_NAME}
    </div>,
    { ...size },
  );
}
```

**なぜ 1-7 より短いのか** — 1-7 の画像は記事ごとに中身が変わるので、`generateStaticParams` で記事の一覧を渡し、原稿を読むために `"use cache"` も要った。トップページの画像は1枚だけで、中身は `SITE_NAME` という決まった文字だけだ。ファイルを読まないので、どちらも要らない。

ビルドして、ルートの表と、各ページの `og:image` を見る。

```bash
bun run build
for p in index posts posts/hello tags tags/mdx; do echo "-- $p"; grep -o '<meta property="og:image\(:alt\)\?"[^>]*>' .next/server/app/$p.html; done
```

ルートの表に1行増える。`○` なので、ビルドの時点で画像ができている。

```
├ ○ /opengraph-image
```

```
-- index
<meta property="og:image" content="https://www.65banseki.dev/opengraph-image?8ec7bf66e2cdb547"/>
<meta property="og:image:alt" content="サイト名を載せた画像"/>
-- posts
<meta property="og:image" content="https://www.65banseki.dev/opengraph-image?8ec7bf66e2cdb547"/>
<meta property="og:image:alt" content="サイト名を載せた画像"/>
-- posts/hello
<meta property="og:image" content="https://www.65banseki.dev/posts/hello/opengraph-image?0203e9bf893d0cb0"/>
<meta property="og:image:alt" content="記事のタイトルと公開日を載せた画像"/>
-- tags
<meta property="og:image" content="https://www.65banseki.dev/opengraph-image?8ec7bf66e2cdb547"/>
<meta property="og:image:alt" content="サイト名を載せた画像"/>
-- tags/mdx
<meta property="og:image" content="https://www.65banseki.dev/opengraph-image?8ec7bf66e2cdb547"/>
<meta property="og:image:alt" content="サイト名を載せた画像"/>
```

画像そのものは `.next/server/app/opengraph-image.body` にある。`open .next/server/app/opengraph-image.body -a Preview` で開くと、白い背景の真ん中にサイト名が出る。

**読み取れること** — トップページのために作った画像が、`/posts` にも `/tags` にも付いた。記事ページだけは、1-7 で作った記事ごとの画像のままだ。準備の2つ目の決まりと同じ形で、自分の画像を持たないページには親（`app/` 直下）の画像が見え、自分のフォルダに画像があるページはそちらで隠れる。一覧ページを X に貼っても、画像のないカードにはならない。
